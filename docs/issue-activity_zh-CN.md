# Issue 活动采集

[English](issue-activity.md)

本改动部署后，现有 `install_launchd.py --statistics` 选项会同时启用独立的 Issue 活动采集。每台机器使用自己的 Multica profile 和角色。本分支不会安装或启用正式采集。暂不支持 Chat，也不推断 Chat 数量。

最多每小时读取一次，在 token 发布之后执行，不依赖用量统计成功。读取分页 issue、完整评论（含已解决讨论）、runs 和仅活动事件的 timeline。CLI 非零退出或截断警告会拒绝本次扫描。失败保留私有事件日志，公开失败状态且没有有效日，不阻断 token 发布；当前快照标为不可用，不表示零任务。

## 私有记录

独立的 `issue-activity-<role>.sqlite3` 放在既有统计缓存目录，权限为 0600。只保存哈希化的 issue/comment/run/event/parent 关联、时间、作者类别、规范化状态和运行触发评论关系。不会保存标题、描述、评论正文、姓名、原始标识或提示词。运行起止时间暂存私有日志，供以后做相同任务年龄的分析；本次尚未发布此类比较指标。

任务归属依次使用当前绑定 runtime、受派 agent 的 runtime、执行记录中唯一已知角色。不明确或未映射的任务排除，并公开扫描量和纳入量。纳入任务的全部 runs 都保留，即使使用多个 harness。跨角色转派尚不能建立互斥的历史归属，因此不能把角色数直接相加当作全工作区去重任务数。父子分类来自结构字段，不是 AI 内容分类。

按哈希化稳定标识去重，更新整条替换；冲突重复拒收。API 后来不再返回的旧记录仍保留，因为缺失不能证明删除。当前任务分布只纳入成功扫描中见到的 issue，但评论数使用保留的历史。迁移时备份私有日志；日志缺失或数量落后于公开记录时拒绝覆盖，不提供自动清空或 reconcile。

## 公开汇总

仅发布 `data/<role>/issue-activity.json`：

- 每日人工、agent、system、未知作者评论数、回复数和新建 run 数。
- 人工评论触发的运行数，以及触发过运行的独立人工评论数，均归到评论创建日。晚到的执行可能修订历史计数；二者比例表示执行放大，不是人工耗时或浪费。
- 状态变化、review 返回执行、done 返回活动状态的次数。它们是流程事件，不代表语义上的验收失败或质量判断。
- 当前任务数与状态计数，以及父任务、子任务、独立任务各自的累计人工评论分布。兼有父节点和子节点的任务归父任务，三类互斥。这不是相同任务年龄的比较。
- 保留记录数量、扫描与纳入数量、未解析关联和未知事件覆盖、扫描状态及版本化生效日期。

不发布逐 issue 行、名称、稳定公开哈希、内容、任务成本、Chat 数量或 AI 健康评分。CI 审计严格公开字段白名单。

## 日期与恢复

首次读到的历史只在本机保留。每日输出从 collectionStarted 开始，不补此前的日期。首次完整扫描成功后的次日才具备资格；当天和次日都成功扫描、当前扫描成功，且保留记录中没有缺失父评论、触发评论或未知评论/状态事件时，已结束日期才有效。实际验证后记录生效日，不预填。成功扫描的零事件日可以有效，漏采日缺失或无效。valid 表示符合当前覆盖契约，不表示永久不变，也不能保证服务端可见记录以外的完整性。

活动指标版本独立于 token/model 统计；计数或归属规则变化时单独升级。现有频率和日历不变。以后判断推进是否费力，仍需区分任务年龄、父子角色和未完成任务。
